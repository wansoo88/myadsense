## 1. ① 무엇이 바뀌나 — 3갈래 분기

| 검수 판정 | 이전 | **지금** |
|---|---|---|
| `severity="high"` | (모순 판정이면 통과했다) | **반려** — ORDER 37 정합성 게이트 |
| `severity="medium"` + passed | 즉시 발행 큐 | **사람 승인 보류**(`dist/pending_approval/`) ← 이번 변경 |
| `severity="none"/"low"` + passed | 즉시 발행 큐 | 즉시 발행 큐(**변화 없음**) |
| 표본 10% 당첨분 | 보류 | 보류(**기능 보존**) |

```python
_HOLD_SEVERITY = "medium"

def _hold_reasons(rv, slug, hsg) -> list[str]:      # 판정을 **읽기만** 한다
    reasons = []
    if str((rv or {}).get("severity", "")).strip().lower() == _HOLD_SEVERITY:
        reasons.append(f"severity=medium(미해소 지적 {n}건)")
    if hsg.get("enabled") and human_gate.is_sampled(slug, hsg.get("sample_pct", 0)):
        reasons.append(f"품질 캘리브레이션 표본({hsg.get('sample_pct')}%)")
    return reasons
```

⛔ **반려가 아니라 보류다.** `passed`·`severity` 를 어디서도 쓰지 않는다(회귀 테스트 `[10](e)` 가 고정).
사람이 승인하면 **그대로 발행**되므로 발행량을 잃지 않는다 — 발행 *시점*만 미뤄진다.

## 2. ② 사람이 보는 것 — slug 만 덩그러니 있던 문제 해결

### (a) 사유 사이드카 `dist/pending_approval/<slug>.reason.txt`

본문 HTML 에는 **손대지 않았다** — 승인 시 그대로 발행되는 산출물이라 배너를 심으면 라이브로 나간다.
대신 같은 디렉터리에 사유 파일을 나란히 둔다. 실제 생성되는 내용(형식 그대로):

```
보류 사유: severity=medium(미해소 지적 3건)
키워드: cheap vps · slug: <slug>
검수 판정: passed=True severity='medium' (상세: dist/review/<slug>.json)

⚠️ 이 글은 검수를 **통과**했다(반려 아님). 검수기가 스스로 medium 을 붙였다는 뜻은
   '내보내도 되지만 지적이 남아 있다'이고, 그 판단이 흔들린 사례가 실측돼 사람이 한 번 본다.
아래 지적이 실제로 남아 있는지 본문에서 확인하라:
  [1] (factual) The '$99/month' HIPAA-compliance tooling price is stated as current fact but …
       → 제안: Remove the figure or hedge it …
  [2] (legal) Definitive negative claim about a named competitor — 'Railway does not offer …'
  AI 티로 지목된 문장: …

승인(발행): python engine/orchestrator.py --approve <slug>
거부(미발행·보존): python -c "import sys;sys.path.insert(0,'engine');from content import human_gate;print(human_gate.reject('<slug>'))"
미리보기: dist/pending_approval/<slug>.html 을 브라우저로 열어라
```

### (b) `--list-pending` 이 사유까지 출력한다

```
$ python engine/orchestrator.py --list-pending
● my-slug
    보류 사유: severity=medium(미해소 지적 3건)
    …(위 본문 전체)
```

### (c) 실제 파일로 확인 — 라이브 가격 오류가 바로 이 화면에 뜬다

실코퍼스의 **진짜 medium 판정**(`bitwarden-vs-1password-…`)을 실제 코드 경로(`_hold_reasons` → `_hold_notice`
→ `human_gate.hold`)에 태워 사유 파일을 생성했다(임시 디렉터리 — 라이브 큐 무오염). 생성 결과 발췌:

```
보류 사유: severity=medium(미해소 지적 2건)
키워드: bitwarden vs 1password · slug: bitwarden-vs-1password-which-password-manager-should-you-use
검수 판정: passed=True severity='medium' (상세: dist/review/…json)

⚠️ 이 글은 검수를 **통과**했다(반려 아님). …
아래 지적이 실제로 남아 있는지 본문에서 확인하라:
  [1] (factual) Bitwarden Premium is described as "roughly $20/year at the time of writing," but
      Bitwarden's individual Premium plan has long been $10/year — the figure appears overstated by ~2x. …
       → 제안: Drop the specific "$20/year" figure … or correct to the actual ~$10/year …
  [2] (coherence) In "Features compared," a bulleted list is collapsed into a single run-on paragraph …

승인(발행): python engine/orchestrator.py --approve bitwarden-vs-1password-…
거부(미발행·보존): python -c "…human_gate.reject('bitwarden-vs-1password-…')"
미리보기: dist/pending_approval/bitwarden-vs-1password-….html 을 브라우저로 열어라
```

> **주목** — 이 지적 [1]이 바로 PM 이 오늘 라이브에서 확인한 그 가격 오류(`roughly $20/year`)다.
> 즉 이 게이트가 그때 켜져 있었다면 **그 글은 발행 전에 사람 손에 걸렸다.** 권고 A 채택의 실증이다.

### 사람이 쓰는 명령 (DoD)


- 승인: 기존 명령 그대로. 사유 사이드카는 큐로 따라가지 않는다(발행 산출물이 아니므로 정리).
- 거부: `dist/review/<slug>.human-rejected.html` 로 **보존**하고 큐에는 넣지 않는다.
  ⚠️ `--reject` **CLI 플래그는 만들지 않았다** — argparse 블록 추가는 이번에 허용된 범위(발행 분기) 밖이다.
  한 줄이면 되니 PM 이 원하면 즉시 붙인다.
