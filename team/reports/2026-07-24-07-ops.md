  - stderr 우선 → stdout JSON `result`(또는 `error`) → 파싱 실패·빈 값이면 stdout 원문 → 둘 다 비면 `(stderr·stdout 모두 비어 있음)`. 300자 컷.
- 실패 처리 **2개소가 이 헬퍼 하나를 호출**하도록 통일(로깅만 변경, 동작 동일):

  - before: `f"...: {((proc.stderr or '') + ' | ' + (proc.stdout or ''))[:300]}"` → 300자 JSON 덤프가 그대로 노출
  - after: `f"claude CLI 실패(rc={proc.returncode}): {_cli_error_detail(proc)}"`
- ⛔ 미변경: 프롬프트(`_user_prompt`·`_SYSTEM`), `_CONTENT_SCHEMA`, `_dict_to_spec`, 그라운딩, 품질 게이트, 재시도 로직.

## 이슈 / 리스크
1. **🔴 경보가 첫 실행에서 실제 고장을 잡았다 — 로컬 20:00 배치도 2026-07-19 이후 0편(5일).** 서버뿐 아니라 **로컬 배치도 같은 침묵 실패** 상태였다. 오늘 20:00 로그에도 `SKIP …: 생성 실패 claude CLI 실패(rc=1):`(사유 공백)이 남아 있다. 즉 **최근 5일간 신규 글이 한 편도 나오지 않았다**(라이브 28편은 07-19 이전 분).
   - 로컬 대화형 세션에서는 같은 CLI 호출이 정상(`pong`) → **콘솔 없는 작업 스케줄러 컨텍스트에서만 실패**하는 문제로 보인다(기존 `stdin=DEVNULL` 방어 주석과 같은 계열). **오늘 밤 20:00 배치부터는 사유가 로그에 찍히므로** 내일 원인을 지목할 수 있다.
2. **⚠️ 알림이 현재 "로그 전용"이다.** 서버 `.env` 에 `TELEGRAM_BOT_TOKEN`/`SLACK_WEBHOOK_URL` **둘 다 없음**(grep 결과 0) → `alerts.send()` 가 콘솔 폴백 → `/var/log/adsense_monitor.log` 에만 남는다. **킬스위치 알림도 동일한 기존 한계**다. 사람이 봐야 알 수 있는 상태이므로, 진짜 푸시 알림을 원하면 자격증명 주입이 필요(사람 결정).
3. 정책 리스크 없음 — 트래픽·클릭 생성 무관, 발행 게이트·cap·킬스위치 로직 무변경. 경보는 발행을 중단하지 않는다.
