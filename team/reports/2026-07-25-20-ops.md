### C. 로그가 비어 있던 이유 (사유 유실) — 비용 0 재현
당시 코드(2026-07-10판, `~/.claude/file-history` 에 보존)는
`raise RuntimeError(f"claude CLI 실패(rc={rc}): {(proc.stderr or '')[:300]}")` 였다.
`CLAUDE_CONFIG_DIR` 을 빈 임시 디렉터리로 돌려 **인증 실패 상태**를 만들어 확인했다(API 호출 전 실패 → LLM 비용 0):

```
rc = 1
stderr = (권한 경고뿐)
stdout = {"is_error":true, ... ,"result":"Not logged in · Please run /login"}
```
→ **rc=1 + 사유는 stdout** 이라는 구조가 확정. 로그의 `claude CLI 실패(rc=1): ` 공백이 설명된다.
오늘 CONTENT 가 고친 `_cli_error_detail`(generator.py:351) 은 stdout 을 읽으므로 **다음 실패부터는 사유가 찍힌다.**

> ⚠️ CONTENT 앞 이관 사항(내 소유 아님): `_cli_error_detail` 은 **stderr 를 먼저** 붙이고 전체를 `[:300]` 로 자른다.
> 위 재현에서 stderr 경고(320자)가 앞을 채워 진짜 사유(`Not logged in · Please run /login`)가 **잘려 나갔다.**
> stdout 의 `result` 를 앞에 두거나 각각 따로 자르는 편이 안전하다.
