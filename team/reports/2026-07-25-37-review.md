## ② "high 지적 존재" 조건 — **구현 불가**, 그래서 구현하지 않았다

PM 지적이 맞다. 내 INTERIM 문구("high 지적 존재 시")는 **부정확했다.** 정정한다.

**현행 스키마에 개별 severity 가 없다.** `review()` 가 검수기에 요구하는 형식(`reviewer.py:553`):

```
"issues":[{"type":"factual|legal|policy|coherence|ai_tone","detail":str,"fix":str}]
```

**실측**: `dist/review/*.json` 58문서의 지적 **236건 중 `issues[i]["severity"]` 를 가진 건 0건.**

내가 INTERIM 에서 "high 지적"이라고 쓴 것의 실제 근거는 **`detail` 문자열의 접두사**였다
(예: `"HIGH: The draft is truncated mid-word…"`, `"LOW — Rendering/encoding defects…"`).
이는 검수기가 임의로 붙이는 **자유 텍스트**이고, 실측 채택률도 **236건 중 13건(5.5%)** 에 불과해 일관되지 않는다.

> **그것을 파싱하는 것은 곧 ORDER 19 가 폐기한 기전 그 자체다** — 자유 텍스트를 패턴으로 분류해 판정에 쓰는 것.
> 방향이 엄격 쪽이라 해도 (a) 근거가 모델의 서식 습관이라 언제든 바뀌고 (b) `"…not a HIGH risk…"` 같은
> 문장에 오작동하며 (c) 5.5% 커버리지로는 게이트라고 부를 수 없다. **하지 않았다.**

**대안(구현 대상 아님, PM 판단용)**: 개별 severity 가 필요하다면 **스키마 자체를 바꾸는 것**이 정공법이다 —
`issues[]` 에 `"severity":"low|medium|high"` 를 추가하고 프롬프트 요구 형식을 고치는 것. 다만 이는
`_SYSTEM`/요청 스키마 변경(=검수 프롬프트 불가침, ORDER 37 경계)에 걸리므로 별도 ORDER 가 필요하다.

## ③ 실코퍼스 영향 측정 (필수 항목)

**규칙 적용 시 통과→반려로 바뀌는 과거 판정: 0건.**

```
코퍼스 59파일(판정 문서 58) · 통과 30건 → 이 규칙으로 반려 전환 0건
  · 전체 기간            : 통과 30건 중 적중 0건
  · 2026-07-05 이후      : 판정 33건 / 통과 12건 / 적중 0건
  · severity 값 분포     : high 18 · medium 17 · low 22 · none 1   (열거값 밖 값 0건)
  · severity="high" 18건 : 18건 **전부** 이미 passed=false  ← 검수기가 자기 규칙을 지킨 사례
```

이 수치는 selftest `[8](e)` 에 붙박이로 들어가 매 실행 재측정된다(발생 시 `WARN` + 파일명 출력).

### 내일 09:00 카덴스에 무슨 일이 생기나 — **아무 일도 없다(구조상)**

- 이 규칙은 **검수기가 스스로 `severity="high"` 를 붙였을 때만** 발화한다. 그 경우 검수기는 이미
  프롬프트상 `passed=false` 를 내야 한다 → 발화 = **모델이 자기 루브릭을 어긴 경우**뿐이다.
- 관측된 위반율: `severity=high` 18건 중 위반 **0건(0%)**. 표본이 18이라 "0"을 단정하진 않는다 —
  rule of three 로 95% 상한 ≈ **3/18 ≈ 17%**. 즉 "드물지만 언젠가 발화할 수 있다"가 정직한 표현이다.
- **정상 통과(severity `none`/`low`/`medium`)는 구조적으로 발화 불가** → 과잉 차단으로 매일 0편이 되는 경로가 없다.
  이 방향은 `[8](c)` 회귀 테스트로 고정했고, 뮤테이션 N2·N5(항상 차단)는 즉시 실패로 잡힌다.

### 발화했을 때의 비용 (config 실값 기준)

`content.yaml on_reject.max_regeneration_attempts=2` → 키워드당 최대 **3회 시도**, `guardrails.yaml rollout.daily_generate=1`.

| 시나리오 | 결과 | 추가 비용 |
|---|---|---|
| 1회차에 발화 → 2회차 정상 통과 | 그날 1편 정상 발행 | 생성 1회 + 검수 1회 (claude CLI 2호출) |
| 3회 모두 반려 | 그날 **0편** | 생성 2회 + 검수 2회 |
| 발화 안 함(관측상 지금까지 전부) | 변화 없음 | 0 |

"3회 모두 반려 → 0편"은 **이 규칙이 새로 만든 경로가 아니다** — 기존 반려(ai_tells·high severity)와 동일한 경로이고,
`generation_watch`(zero_generation_alert_days=2)가 이미 감시한다.

## ⑤ 회귀 테스트 — `[8]` 신설 + 뮤테이션 검증

`engine/content/reviewer_selftest.py` `[8] 모순 판정 차단` (25항목). 양방향으로 친다:

- **(a) 단위 진리표** — `high`/`HIGH`/`" High "` → 모순 / `none`·`low`·`medium`·`unknown`·`None`·`["high"]`·`"higher"` → 모순 아님 / `passed=False`+`high` → 모순 아님.
- **(b) end-to-end** — `passed=true`+`high`, `passed="ok"`+`high`, `passed=true`+`HIGH` 세 경우가 `review()` 를 통과하며 **반려**되고 orchestrator 게이트가 막는지. `severity` 원본 보존 · `notes` 에 사유 기록도 함께 검증.
- **(c) 반대 방향** — `passed=true`+`none|low` 는 **그대로 통과**, `passed=true`+`medium`+지적 1건도 **통과**(임계 임의 강화 방지 회귀).
- **(d) ORDER 19 경계** — `_apply_disclosure_policy` 본문에 새 로직이 새어 들어가지 않았는지 소스 검사.
- **(e) 실코퍼스 영향** — 매 실행 재측정, 발생 시 `WARN` + 파일명.

## 경계 준수

- 수정 파일: `engine/content/reviewer.py` · `engine/content/reviewer_selftest.py` — **둘 다 REVIEW 소유**(PM 승인분).
- **push 0건 · 발행 0건 · 배포 0건 · 서버 접속 0건 · LLM 호출 0회**(셀프테스트·하네스 모두 네트워크 미사용).
- `passed` 를 True 로 만드는 코드는 **한 줄도 추가하지 않았다**(추가된 대입은 `data["passed"] = False` 하나뿐).
- 불가침 영역 무변경: `_SYSTEM` 프롬프트 · `quality_gate` · `ai_tells` 자동반려 · `_apply_disclosure_policy` 본문.
- 임계 임의 변경 없음(medium·열거값 밖 severity 미차단, 회귀 테스트로 고정).
