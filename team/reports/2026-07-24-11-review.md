## ④ 회고 — 게이트는 언제부터 실질적으로 막고 있었나

- **12,000 상한은 처음부터 있었다.** `f979ef9`(06-28) 도입 이후 `61e37e6`·`bc6658f`·`62e035e`·`7e57c69` 5개 커밋 내내 **불변**.
- **막기 시작한 건 글이 길어지면서다.** 검수 판정 50건에서 "글이 잘렸다" 지적: 06-28~06-29 **2/18** → 07-02 **2/5** → **07-24 4/4 (100%)**.
- **통과선이 내용이 아니라 길이였던 정황**: 통과한 글이 상한 바로 아래에 몰려 있다 — `nordvpn…premium-vpns`(07-14) 11,933자 = **상한 67자 아래**, `orca-vs-herdr` 11,851, `otter-ai` 11,385. 반면 상한을 넘긴 글은 뒷부분이 통째로 안 보인 채 판정됐다.
- **더 심각한 쪽은 반대 방향이었다**: 상한 초과 16편 중 **VERDICT 미검수 10편·SOURCES 미검수 14편**. VERDICT 는 최종 권고·최상급·경쟁사 단정이 몰리는 **법적 리스크 최고 구간**이고, SOURCES 는 E-E-A-T 근거다. 그 구간이 검수되지 않고 발행됐다.
- 게다가 상한 초과가 **항상** 반려로 이어지지도 않았다(초과했는데 PASS 된 글 존재) → 같은 결함이 어떤 날은 HIGH 반려, 어떤 날은 무시. **판정이 도구 산물에 좌우돼 비결정적이었다**는 뜻이고, 게이트로서 최악의 성질이다.

## 이슈 / 리스크
- **반려 초안 미보존(구조)**: `orchestrator.py` 가 통과분만 저장 → 반려 원인 사후 검증 불가. 오늘 4건은 이미 소실. `reviewer.py` 쪽 입력 로그로 **앞으로는** 재현 가능하게 했으나, **초안 spec 자체 보존은 OPS 소유 파일**(`orchestrator.py`)이라 내가 손대지 않았다.
- **지시 범위 초과 3건 — PM 확인 요망**: ①소스 상한 5,000→20,000 ②바이라인·날짜 입력 추가 ③입력 로그. 셋 다 "검수기가 보는 입력" 계열이고 판정 기준을 건드리지 않지만, 지시서에 명시된 3종 밖이다. **거부하시면 되돌린다.** (소스 상한은 검수 1회당 입력 토큰이 최대 ~4k 토큰 증가)
- **비용**: 본문 상한 상향으로 검수 1회 입력이 최대 ~7k 토큰 증가. 판정 출력(`max_tokens=4000`)은 불변.
- **정책 리스크 없음**: 무효 트래픽·트래픽 생성 관련 코드 없음(G4). 킬스위치 트리거 없음.
