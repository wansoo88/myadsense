## ① `_coerce_passed` 를 뚫어봤다 — 양방향

### (a) 느슨해지는 방향: 약화 0건

검수기가 낼 법한 값 **99종** + 무작위 문자열 **200,000종** + 비정형 타입 14종을 구/신 동작으로 대조했다.
기준: 구판(`data.setdefault("passed", False)` → `if not rv.get("passed")`)에서 **차단**되던 값이 신판에서 **통과**로 바뀌면 약화.

```
총 99종 — 약화(구=차단→신=통과) 0건 / 강화(구=통과→신=차단) 67건 / 동일 32건
무작위 문자열 200,000종: 구=차단 → 신=통과 로 뒤집힌 사례 0건
비정형 타입 14종(object/bytes/tuple/set/complex/range…) 중 통과 인정: 0건
```

강화된 67종에는 `'false' 'False' 'FALSE' 'no' 'n' 'f' '0' 'fail' 'unknown' 'pending' 'n/a' 'null' 'maybe' 'partial'
'borderline' [True] {'passed':True} 2 -1 0.5 nan inf` 이 포함된다 — **구판에서는 이것들이 전부 발행 게이트를 통과했다.**
화이트리스트(`true/yes/y/t/1/pass/passed/ok`)가 과하게 넓지 않은지도 봤는데, 8종 중 "반려 의도인데 통과로 읽힐"
현실적 후보는 없었다(`ok` 가 유일하게 애매하나, `"ok"` 를 반려로 쓰는 검수기 출력은 코퍼스에 없다).

### (b) 엄격해지는 방향의 오탐 — R6(낮음)

반대로 **통과 의도인데 반려로 떨어지는** 값이 있다:
`approved · approve · accept · accepted · okay · 'true'(따옴표) · "true" · **true** · TRUE. · true, · 통과 · 예 · 합격 · '1.0' · '01' · 'true (with minor issues)'`
방향은 안전(fail-closed)하고, 실코퍼스에 문자열 판정 자체가 0건이라 실피해는 없다. 다만 이 경우 로그에는
`REVIEW REJECT … sev=none` 처럼 **판정과 severity 가 어긋난 채** 찍혀 원인 추적이 어렵다 → 제안 P3.

### (c) 진짜 구멍은 다른 곳에 있다 — **R1 (높음, 발행 게이트)**

정규화는 `passed` 의 **타입**만 본다. **판정 정합성(passed ↔ severity ↔ issues)은 어느 단계도 검사하지 않는다.**
`review()` 전 경로에 검수기 응답만 갈아끼워 실측한 결과:

| 검수기 응답 | 결과 |
|---|---|
| `{"passed":true,"severity":"high","issues":[{"type":"legal","detail":"false first-person testing claim: I ran it for 8 weeks"}]}` | **★발행 통과★** |
| `{"passed":true,"severity":"medium","issues":[defamation, solicits ad clicks, fabricated price]}` | **★발행 통과★** |
| `{"passed":"ok","severity":"high","issues":[{"type":"legal","detail":"defames a rival"}]}` | **★발행 통과★** |
| `{"passed":"false", …}` | 차단 (이번 커밋의 성과) |
| `passed` 키 누락 / 중첩 오브젝트 / 배열 응답 / 평문 | 차단 또는 예외→미발행 |

`ai_tells` 만 유일하게 교차검사를 받는다(`reviewer.py:533` — 하나라도 있으면 `passed=False`).
`severity`·`issues` 에는 같은 장치가 없다. 실코퍼스(`dist/review/*.json` 58건 판정) 실측:

```
2026-07-05(ai_tells 엄격 게이트 도입) 이후 판정 33건 / 통과 12건
  · 통과 12건 전부 미해소 `issues` 1건 이상 보유
  · 그중 3건은 severity=medium 상태로 통과·발행 (bitwarden-vs-1password 07-08, fly-io-vs-railway 07-10, nordvpn-vs-expressvpn 07-10)
  · passed=true + ai_tells>0 : 0건  ← ai_tells 게이트는 정상 작동
  · passed=true + severity=high : 0건  ← 아직 관측 안 됨(구멍은 열려 있으나 발화 사례 없음)
```

> 판단: 프롬프트가 "passed=false if any **high**-severity issue" 라고 지시하므로 medium 통과는 설계대로다.
> 문제는 **모델이 그 지시를 어겨 high 를 붙이고도 통과라고 답하면 아무도 막지 않는다**는 것이다.
> `_coerce_passed` 의 docstring 은 "fail-closed" 라고 쓰지만, 그 fail-closed 는 **타입 층에만** 성립한다.

커밋 메시지·원장의 "실코퍼스 59문서·표식 25건에서 **손실 0건**" 은 **`issues` 배열 길이 기준으로만** 참이다.

표식 지적이 `issues` 에 남으면서 슬롯을 하나 먹으므로, **지적이 7건 이상인 문서에서는 뒤쪽 지적이 밀려난다.**

실코퍼스 리플레이(표식 25건 중 `issues>6` 인 4문서) → **2문서에서 실제 탈락 발생**:

```
best-cheap-vps-in-2026-a-buyer-s-guide-…  issues=12, 표식 위치=[3]
   → 밀려난 지적: [legal] "Definitive negative statement about a named competitor: 'DigitalOcean's homepage
      does not lead with price…' … and 'the fetched text' exposes the scraping pipeline to readers"
proton-pass-vs-bitwarden-which-password-manager-…  issues=8, 표식 위치=[4]
   → 밀려난 지적: [coherence] "Rendering/encoding defects in the body text: raw HTML …"
```

밀려난 것이 **경쟁사 부정 단정 + 파이프라인 언어 노출(legal)** 이다 — 루브릭 ④가 정확히 막으려는 유형이다.
`move` 였다면 이 지적이 피드백에 들어갔다. 즉 **copy 는 "잃는 것이 없다"가 아니라 "잃는 대상을 바꾼다."**
(발행 게이트에는 영향 없음 — 두 문서 모두 `passed=false` 로 반려된 건이고, 손실은 재작성 품질에만 걸린다.)

부가 관측: 표식 25문서 합계 피드백 길이 **53,878자 → 64,022자(+18.8%)** — 재작성 프롬프트 비용도 그만큼 늘었다.

| M3 블랙리스트 방식(`false/0/no`만 False) | 1 | [5]×2 |
| M4 화이트리스트에 `unknown/pending` 추가 | 1 | [5]×2 |
| M5 항상 True | 1 | [5]×2, [6]×3 |
| M6 항상 False(과잉 엄격) | 1 | [5]×1, [6]×1 |
| M7 `strip/lower` 제거(대소문자 미처리) | 1 | [5]×1 |
| M8 `copy`→`move` 되돌리기 | 1 | [2], [4], [7]×2 |
| M9 폐기된 판정 뒤집기 부활(ORDER19 위반) | 1 | [1c]×6, [2]×252, [2b]×222 |

베이스라인은 rc=0·FAIL 0. **거짓 통과(mutant 미탐지)는 0건.** M8 이 `[7]` 로 잡힌다는 것은
"`copy` 의 실익"을 재는 테스트가 실제로 작동한다는 뜻이고, M9 가 474건으로 잡힌다는 것은
ORDER 19 불변식 테스트가 살아 있다는 뜻이다.

### (b) `[6]` 의 몽키패치는 가짜 증명인가 — 아니다

`review()` 실행 중 실제로 호출된 프로덕션 함수를 계측했다(3회 = `[6]` 의 케이스 3개):

```
_flatten 3 · generator.scan_ai_cliches 3 · monetization_state 3 · _system 3
generator._extract_json 3 · _coerce_passed 3 · _apply_disclosure_policy 3
```

우회된 것은 **`generator.complete_text`(LLM 호출)와 `_dump_input`(파일 쓰기) 둘뿐**이다.
JSON 추출·정규화·고지 후처리·`ai_tells` 강제·프롬프트 조건화는 전부 실제 코드가 돈다 → **실경로 우회 아님.**

**남는 한계 3가지(참고):**
- `[6]` 단독으로는 M3·M4·M7(화이트리스트 조작)을 못 잡는다 — `[5]` 가 잡는다. 두 테스트는 **상호 보완이며 중복이 아니다.**
- `[6]` 은 클리셰 사전필터 경로(`scan_ai_cliches` 적중 시 LLM 미호출 즉시 반려)를 타지 않는다. 실측으로는 정상 동작 확인
  (`in today's fast-paced world` 포함 초안 → LLM 응답이 `passed:"true"` 여도 `passed=False`).
- `[5]`(a)의 전제 검사는 `orchestrator.py` 에서 `if not rv.get("passed")` 문자열 존재만 본다 — 게이트 표현식이 바뀌면
  먼저 깨지도록 설계돼 있고, 실제로 그렇게 동작한다(읽기 실패 시엔 `warn` 으로만 떨어짐).

| # | 대상 | 소유 | 제안 |
|---|---|---|---|
| **P1** | 라이브 2편 고지 문구 | CONTENT(문구)·OPS(재배포) | 허위 고지 문장 제거 후 재배포. 재발 방지로 `site_builder`/`renderer` 에 **미수익화 상태 문구 고정**(현재 `/privacy/`·`/about/` 문구와 동일)만 렌더하고, 본문 생성 모델이 고지 문장을 쓰지 못하게 프롬프트에 금지 명시 |
