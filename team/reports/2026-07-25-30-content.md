## 5. 🔴 핵심 발견 — 이 파일럿의 전제가 성립하지 않는다

ORDER 근거는 "26-content 새 구조는 신규 생성분부터 적용 → 기존 글은 재생성해야 바뀐다"였다.
**comparison 유형에는 적용되지 않는다.** 근거 2개(코드 + 실측):

**(a) 코드** — `engine/content/renderer.py` `render()` 의 `_ORDERS`:
```python
"comparison": [b_summary, b_headtohead, b_matrix, b_pricing, b_proscons, b_ad, b_body, b_verdict, b_faq]
"guide":      [b_summary, b_ad, b_headtohead, b_matrix, b_body, b_pricing, b_proscons, b_verdict, b_faq]
"listicle":   [b_summary, b_picks, b_headtohead, b_matrix, b_pricing, b_ad, b_body, b_proscons, b_verdict, b_faq]
```
comparison 배열은 **26-content 이전의 고정 순서와 같다**(26-content 보고서 §4.3 "비교글은 결정 먼저가 옳아 순서 유지").
라벨도 `In short`/`Verdict` 그대로. → comparison 글은 재생성해도 골격이 **한 글자도** 안 바뀐다.

**(b) 실측** — 새 렌더러로 comparison spec 을 렌더한 결과 H2 골격이 옛 글과 동일(§4.2, 그리고 fixture 렌더 검증에서도 동일).

**교집합 문제**: 25-growth §1-1 의 crawled-not-indexed 10편 = 홈 1 + `/compare/` 9편, 그리고 그 9편은
**전부 `page_type=comparison`**(kicker 실측). 즉 **"색인 보류 그룹" ∩ "구조가 바뀌는 유형(guide·listicle)" = 0.**
26-content 의 구조 차별화 효과를 받는 guide 3편·listicle/alternatives 4편은 모두 `unknown to Google`(아직 크롤조차 안 됨) 그룹이다.

→ **PM 판단 필요**(§7 선택지). 이번 파일럿이 실제로 검증하는 가설은 "골격 차별화"가 아니라
**"본문·데이터를 새로 쓰고 dateModified 를 갱신하면 재평가되는가"** 뿐이다. 그 가설도 유효하지만, 26-content 의
효과 검증은 아니다.

## 6. ③ 산출물 — 재생성 도구

**`engine/content/regen.py`** (신규, 내 소유 영역. 타 소유 파일 **0줄 수정**)

```powershell
python engine/content/regen.py --plan-only --slug <slug>            # LLM 호출 없이 불변값·키워드만 확인
python engine/content/regen.py --slug <slug> [--slug <slug> ...] --max-attempts 2
```

설계 요점:
- **URL 불변 고정**: 생성 직후·렌더 **직전에** `slug`/`canonical`/`published_at`/`cluster` 를 **원본 HTML 에서 읽은 값**으로 덮어쓴 뒤 재렌더. `_dict_to_spec()` 이 모델 제목으로 slug 를 새로 만드는 경로를 차단한다. `updated_at` 만 오늘로.
- **키워드 자동 해석**: `published.json` 키워드 중 `slugify(kw)` 가 slug 의 최장 접두인 것을 고른다(cursor-vs-windsurf ↔ cursor-vs-github-copilot 오매칭 방지). `--keyword` 로 수동 지정 가능.
- **우회한 것은 스킵 로직뿐**: `quality_gate.check` · `reviewer.review` · `human_gate.is_sampled` 를 파이프라인과 **동일 인자로** 호출. 통과 못 하면 큐에 **아무것도 쓰지 않는다**.
  - 게이트가 실제로 살아 있음 증명: 샌드박스 스모크 테스트에서 얇은 fixture 초안이 `structure: 산문 부족(59 < 300 words)` 로 **정상 반려**됨.
  - `human_sample_gate`: 3편 모두 해시상 미샘플(61·29·87 ≥ 10)이라 이번엔 발동 안 함. 발동 시 큐 대신 `dist/pending_approval` 로 보내도록 그대로 구현.
- **실행 직전 자동 백업**(queue·review·site) → `dist/backup/<ts>-regen/MANIFEST.json`.
- **⛔ 미접촉**: `engine/store/published.json`, `last_publish_date.txt`(일일 카덴스·중복 가드 오염 방지), 발행·배포·서버.
- 기존 감사 이력 보호: 판정을 `dist/review/<slug>.json` 이 아니라 **`<slug>.regen.json`** 에 쓴다.
