구판 `_apply_disclosure_policy` 의 마지막 분기가 판정을 뒤집던 곳이다:


현행(`reviewer.py:344-395`)에는 `data["passed"]`/`data["severity"]` **대입이 한 줄도 없다.**

구판 308~393행(**86줄**)을 통째로 삭제했다. 모듈에서 심볼이 사라졌음을 테스트가 매 실행 확인한다(`[1b]`):

### 1-3. 남긴 것 (판정 경로 아님)
- `_ABSENCE_OF_DISCLOSURE`(`:297`) · `_OTHER_RISK`(`:320`) → **표식 부착 판별 전용**. 주석에 "라벨링 보수성에만 쓴다"고 명시(`:315-318`).
- `monetization_state()` fail-closed(`:157-207`) — ORDER 18 ③ 처리분 **유지 확인 완료**(아래 §3 실측).
- 강등(=`issues_not_applicable` 로 이동 + 사유 보존)은 지시대로 유지. 사유 문구는 "판정을 바꾸지 않았다 / 다른 결함이 섞여 있으면 그 결함은 그대로 유효하다"로 고쳐 썼다(`:379-385`).

### 1-4. 프롬프트 조건화 — 손대지 않음 (양방향 확인)
`_SYSTEM` 은 **커밋된 HEAD 판과 바이트 동일**:
```
HEAD _SYSTEM sha1 = 1b5f48f7d8eff8d96e2f777b9bd54287275fa06e
NOW  _SYSTEM sha1 = 1b5f48f7d8eff8d96e2f777b9bd54287275fa06e   identical = True
```
`_system(state)` 동작(테스트 `[3]` 실측):
- `OFF`(미수익화 관측) → 고지 절 **제거** + 근거 주석 부착 ✅ (오탐 해소의 본체, 살아 있음)
- `ON`(수익화 관측) → 고지 절 **유지** ✅
- `UNKNOWN`(관측 실패) → 고지 절 **유지** ✅ (fail-closed)

`ai_tells` 자동반려(`:485-488`)·severity 임계·`quality_gate` 는 무변경.

## 2. 불변식 증명 (테스트 `[2]`·`[2b]`·`[4]`)

`_apply_disclosure_policy` 실행 **전후로 `passed`·`severity` 가 항상 동일**함을 다음 규모로 친다.

| 대상 | 조합 | 결과 |

| 단건 케이스 44종 (기존 15 + rev2 구멍 8 + **감사 21종**) | × 3상태(OFF/ON/UNKNOWN) × 6판정 = **792회** | 판정 변경 **0** |
| 감사 21종 × 순수고지 동반 조합 | × 18조합 = 378회 | 판정 변경 **0** |

| **실코퍼스** `dist/review/*.json` | **56문서 · 229지적 × 3상태** | `verdict_changed=0` |

### 감사 21종의 출처 — 정직하게
**감사자가 창작한 원문 21종은 리포에 보존돼 있지 않다**(`team/reports/**`·`dist/review/**` 전수 검색 0건).

## 4. ⚠️ 부작용 2건 — 숨기지 않고 보고 (PM 판단 요청)

얼라우리스트(`_out_of_scope`)를 제거하면서 **표식 판별의 폭이 rev2 수준으로 돌아왔다.**
판정은 불변이지만, '고지 누락 + 실질 결함'이 **한 지적에 섞이면 그 지적에 표식이 잘못 붙는다**(합성 8종 중 6종).

```
WARN  표식 오부착 6/8종 — HOLE V1 false first-pers, V2 invented pricing, V3 defamatory claim,
      V4 YMYL health dire, V5 absolute superla, V6 invented quote
      (판정 영향 없음. 부작용: 재작성 피드백 누락·보고서 분류 오기. 실코퍼스 발생 0건)
```

**(a) 재작성 피드백 누락** — 표식된 지적은 `issues` 에서 빠진다. `orchestrator.py:229-231` 이 `rv["issues"]` 로
재작성 피드백을 만들므로, 오부착되면 그 결함이 재작성 모델에 전달되지 않는다. (게이트는 무관 — `orchestrator.py:222` 는 `passed` 만 본다.)
**(b) 보고서 분류 오기** — 사람이 보는 `issues_not_applicable` 칸에 실질 리스크가 놓인다.
→ 사유 문구에 "⚠️ 다른 결함이 섞여 있으면 그 결함은 그대로 유효하다 / 이 라벨은 어휘 추측이며 혼합 지적에 과매칭한다"를 박아 완화했다(`reviewer.py:383-385`).

**실데이터 발생 0건**: 코퍼스 229지적 중 표식된 25건을 **전문 육안 확인**했고 **전부 순수 고지 지적**이었다(혼합 0건).
구판 얼라우리스트가 막던 4건(`best-cheap-vps…buyer-s-guide` · `cheap-vps…how-to-judge` · `how-to-self-host-a-ghost-blog` · `nordvpn-vs-expressvpn…which-vpn`)도
전문을 읽어보니 전부 순수 고지 지적이었다 — 구 얼라우리스트는 과억제(정당한 표식을 21건으로 깎던 쪽)였던 셈이다.

**PM 판단 요청 (다음 라운드 후보, 이번엔 지시대로 '옮기기'를 유지했다)**:
표식을 **옮기기(move) 대신 복사(copy)** — 지적을 `issues` 에 남긴 채 `status/reason` 만 달고 `issues_not_applicable` 에도 싣는 방식으로 바꾸면
