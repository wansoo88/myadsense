## 먼저 PM 의 잘못을 밝힌다
DoD 2·3(신규 1편 생성·검수결과 제시) 미충족은 **워커 책임이 아니다.** 하달 시 PM 이
"이번 ORDER 에서는 코드·프롬프트 수정까지만 하고 실제 글 생성 실행은 하지 마라" 고 **지시서와 모순되는 제약**을 걸었다.
워커는 지시대로 했고 `done=false` 로 정직하게 보고했다. 감사자의 REJECTED 는 지시서 기준으로 정당하나,
**원인은 PM 의 지시 충돌**이다. 아래로 정정한다.

## rev 2 작업 (코드 — 감사에서 나온 진짜 문제)
- [ ] **파이프라인 언어 정규식 오탐 해소(우선순위 1).** 개발툴 비교 사이트인데 개발 어휘를 금지하고 있다. 실측:
      `"Postman displays the parsed response body, and the fetched JSON is cached"` → 2건 오탐(`fetched`·`parsed`),
      `"Scraped data can be exported to CSV"` → 1건. 매 초안에 불필요한 재작성 1회(LLM 비용)를 유발하고
      **정확한 기술 용어를 빼도록 모델을 압박**한다. → 금지 대상은 *단어* 가 아니라 **생성 과정을 자백하는 문맥**
      ("the fetched text", "in the version reviewed", "sources supplied", "source material") 이다. 문맥 기반으로 좁힐 것.
- [ ] **셀프체크 게이밍 대응.** 표면 토큰 3개(`How we chose:` · `as of ...` · `Our pick is ...`)만 덧대면 7건 → 0건이 된다(감사자 실측).
      플래그 문구가 재작성 피드백으로 주입되므로 **모델이 근거 없이 지목하고 지어낸 수치에 관측일을 붙여 '합격'할 유인**이 있다.
      → 최소한 (a) 플래그 문구를 피드백에 그대로 노출하지 않거나, (b) 토큰 존재가 아니라 **근거(출처 링크·소스 인용) 동반 여부**를 보게 할 것.
      셀프체크는 게이트가 아니라 보조 신호임을 코드 주석으로 명시.
- [ ] **`config/topics.yaml` 의 `title_policy` 는 코드가 읽지 않는다**(engine 전체 grep 0건). 값을 바꿔도 동작이 안 바뀌어
      "config 주도" 착시를 만든다 → **코드가 읽게 배선하거나, 읽지 않으면 config 에서 빼고 프롬프트에 둘 것.** 둘 중 하나.
- [ ] AI 리듬 임계값이 기존 코퍼스 상위 극단에 맞춰져 사실상 발화하지 않는다(미러 3 → 28편 중 2편). **현재 우리 리듬을 정상으로 승인**하는 셈이니, 임계값 근거를 재검토하거나 "프롬프트가 주 방어선"임을 명시.
