## 목적 (왜)

사람이 오늘 텔레그램 토큰을 서버 `.env` 에 주입했고 **도달 테스트가 성공**했다(`alerts.send() -> True`).
그런데 **알림이 실제로 나가는 지점이 두 곳뿐**이라, 사람이 기대하는 "실패하면 알려준다"와 어긋난다.

현재 커버리지 (실측 — `grep alerts.send engine/`):
- ✅ `orchestrator.py:298` 킬스위치 발동 (monitor 매시간)
- ✅ `generation_watch.py:86` 생성 중단 **임계 2일** 초과
- ❌ **`daily.sh` 실패(rc=1) → 알림 없음.** git pull 실패·selftest 실패·generate 실패·deploy 실패가
  전부 로그에만 남는다. crontab 에 `MAILTO` 도 없다(실측).
- ❌ **당일 0편 → 알림 없음.** 게다가 과거 21일간 0편일 때 **rc=0(로그상 정상)** 이었다 —
  rc 만 보면 이 사고를 다시 놓친다.

## 작업

- [ ] **① `daily.sh` 실패 전파 지점에 알림을 붙여라.** 이미 마지막에 rc 를 모아 `exit 1` 하는 블록이 있다
      (`pull_rc`·`st_rc`·`gen_rc`·`dep_rc`). 거기서 **어느 단계가 왜 실패했는지** 한 줄로 텔레그램에 보낸다.
      - ⚠️ **알림 실패가 파이프라인을 죽이면 안 된다** — 비치명적으로(`|| true`) 감싸라.
      - ⚠️ 킬스위치 halt 로 조기 종료하는 경로(`exit 1`)도 같은 처리가 필요하다. 빠뜨리지 마라.
      - 메시지에 서버 시각·실패 단계·재현 명령을 넣어 사람이 SSH 없이도 판단할 수 있게 하라.
- [ ] **② 당일 0편 감지를 권고하라.** `generation_watch` 임계는 현재 **2일**이다. 하루 1편 카덴스에서
      "어제도 오늘도 0편"이어야 알림이 가므로 **최대 이틀을 모르고 지나간다**.
      1일로 낮출 것인지, 아니면 ①이 생겼으니 2일 백스톱으로 두는 게 맞는지 **근거를 들어 권고**하라.
      (오탐 비용 = 큐 소진·정상 스킵 같은 사유로 알림이 울리는 경우를 따져볼 것.)
      ⛔ 임의로 바꾸지 말고 **권고만** 하라 — 임계 변경은 PM 승인 사항이다.
- [ ] **③ 실제로 실패를 주입해 도달을 증명하라.** 예: 일시적으로 존재하지 않는 스테이지를 호출하거나
      `SELFTEST_BLOCK_GENERATE` 경로를 태워 rc≠0 을 만든 뒤, 텔레그램에 메시지가 **실제로 도착**하는지 확인.
      ⛔ 증명 후 원상복구하고, **라이브 사이트·발행 상태를 건드리지 마라**.
